# 交付证据 — 登录启动与设备自动重连

## 入口与环境

与 #1 共用当前菜单栏应用。系统设置 → 通用 → 登录项与扩展中已实际看到“TVVT 散热器”位于“登录时打开”，应用面板显示已启用。

## 过程证据

- 连接状态机测试：记住目标、排除同型号其他设备、单次连接门、2～60秒退避、主动暂停跨睡眠保留、恢复及重启默认状态，全部通过。
- 实际主动断开后约79秒未发生自动连接，点击恢复后成功连接并收到新鲜状态与控制确认。
- 实际重新启动日志确认 `restored mode=fullSpeed, rememberedDevice=true`。随后因最终重签名触发系统授权未完成，不能声称重启后已完成实机重连。

## 怎么验

允许最终开发版蓝牙权限后，重新打开应用应连接记住的T23SS；主动断开应保持暂停。重新登录和实际睡眠唤醒需安排在不打断当前工作的时间验证。本次未执行注销、重启或强制休眠，相关AC保持未完成。

上文临时签名授权阻塞为历史记录，现已解除。日常入口改为 `/Applications/TVVT 散热器.app`，使用 `./install.sh` 更新。固定证书后从 0.2.0 更新至 0.2.1，未再次出现蓝牙授权请求；启动日志为 `authorization=3`、记住 fullSpeed 和目标设备，自动连接 T23SS 并收到控制 ACK。证书绑定的 designated requirement 在不同内容构建间一致。

三组测试、签名校验通过；重复运行签名配置不重新创建证书，不可用签名身份构建失败且不退回临时签名。实际注销登录及睡眠恢复仍未执行，相关 AC 不代勾。详细证据见 [签名复验](../02-automatic-cooler-lifecycle/signing-verification.md)。
