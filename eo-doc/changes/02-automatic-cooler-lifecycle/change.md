# 登录启动与设备自动重连

## §1 解决什么问题

用户不希望每次手动开应用和连接散热器。依赖 #1 的共享控制模型和菜单栏，在登录后自动运行，并恢复对已选设备的控制。

来源：[头脑风暴记录](../../../.eo-project/brainstorm/2026-10-31-自动温控与菜单栏.md)。继承全部已钉决定，本项落实无人干预的应用与连接生命周期。

已钉决策：
- 登录 Mac 后自动运行，菜单栏持续可见状态和温度；关闭控制窗口不退出后台控制。
- 首次由用户选定散热器后记住设备身份，不按同型号名称盲选附近设备。
- 之后启动、意外断连和睡眠唤醒自动重连；主动断开则暂停自动重连。
- 双模式与 36W 请求规则继承 #1，不新增应用功率限制。

建议细化（用户已确认）：
- 首次运行启用系统支持的登录项注册，系统要求用户允许时明确显示待批准状态，不冒充注册成功。
- 记住所选模式；新安装默认自动。主动断开暂停到用户点击连接或重新启动应用；睡眠唤醒不清除该暂停。
- 蓝牙未开或权限未授予时等待系统状态恢复，不反复弹窗；恢复后仅连接记住的设备。

## §2 完成后我应该看到什么

- [ ] AC-1 [自动·阻塞] 首次完成登录项启用后，系统登录项状态与应用显示一致；退出再登录 Mac，应用自动出现于菜单栏。系统待批准、拒绝或注册失败时明确提示原因。
- [ ] AC-2 [自动·阻塞] 首次选择并成功连接设备 A 后，重新打开应用会自动连接 A；附近有同型号 B 时不会替用户连接 B。A 不在附近时持续显示等待或重试状态，仍可手动选择设备。
- [ ] AC-3 [自动·阻塞] A 意外断连、断电后恢复、系统蓝牙关闭再开启或 Mac 睡眠再唤醒后，会重试连接 A；每次只有一个有效连接尝试，重试间隔有上限并退避，不密集循环。
- [x] AC-4 [自动·阻塞] 点击断开后不会立即自动连回，睡眠唤醒也不擅自取消暂停；再次点击连接或重新启动应用后恢复连接流程。
- [ ] AC-5 [自动·阻塞] 关闭主控制窗口仍能从菜单栏看状态和切换两个模式；重新开窗口不创建第二个控制器。重新连接后，只有获取新鲜设备状态且通道就绪时才恢复选定模式，自动模式还需新鲜本机温度。
- [ ] AC-6 [自动·阻塞] 重新启动保留上次模式与目标设备；等待连接时不显示成已连接或已执行全速。构建及既有温控/协议测试继续通过。

## §3 谁验收、按什么标准

实施者以模拟生命周期事件和实际设备组合验证连接状态机与去重；在当前 Mac 记录登录项注册状态、实际重新登录启动、休眠恢复、主动断开及设备断电恢复证据。无法实际重新登录或无设备时，相关 AC 保持未验证。
./build.sh 和 ./test.sh 回归通过，不以调用系统注册 API 成功替代实际登录启动验证。

## §4 不通过怎么办

阻塞项未通过不得归档。平台注册或签名问题先诊断，不未经用户裁决改成 root 守护进程。应用路径变化导致登录失效需修复安装/注册流程并复验。
